Если в MongoDB используется такая цепочка: "Сервер -> База данных -> Коллекция -> Документ", то в PostgreSQL
используется такая цепочка: "Сервер -> База данных -> Схема -> Таблица -> Строка".

Схемы в PostgreSQL это не аналогия схем из Mongoose. Схемы в PostgreSQL просто позволяют разделить БД на несколько
подразделов. При создании БД внутри нее всегда автоматически создается одна схема с именем "public".

/*--------------------------------------------------------------------------------------------------------------------*/

В отличие от MongoDB, PostgreSQL при установке на Windows по умолчанию устанавливается как системная служба и
запускается автоматически вместе с Windows.

pgAdmin4 - это GUI СУБД для управления БД, использующих PostgreSQL.

В pgAdmin4 вверху слева в разделе "Object Explorer":
1. На самом верхнем уровне находятся группы серверов. Изначально есть группа серверов "Servers".
2. Внутри групп серверов находятся отдельные сервера. В группе серверов "Servers" изначально есть сервер
"PostgreSQL 18", который содержит дефолтную техническую БД "postgres", создаваемую при установке PostgreSQL.
3. Внутри каждого сервера есть разделы "Databases", "Login/Group Roles" и "Tablespaces".
4. Раздел "Databases" содержит список БД на сервере. Таблицы лежат по пути "Databases" -> "postgres" -> "Schemas" ->
"public" -> "Tables".
5. Раздел "Login/Group Roles" содержат пользователи и роли сервера. В сервере "PostgreSQL 18" изначально создается
суперпользователь "postgres" и 16 системных ролей, которые нужны для внутренних механизмов.
6. Раздел "Tablespaces" содержит пути к папке на диске, куда PostgreSQL записывает файлы таблиц.

Числовые типы в PostgreSQL:

1. smallint:
1.1 Используется для небольших целых значений.
1.2 Имеет размер 2 байта.
1.3 Имеет диапазон от −32768 до 32767.

2. integer (int, int4):
2.1 Используется для целых значений.
2.2 Имеет размер 4 байта.
2.3 Имеет диапазон от −2147483648 до 2147483647.

3. bigint (int8):
3.1 Используется для больших целых значений.
3.2 Имеет размер 8 байт.
3.3 Имеет диапазон от −9223372036854775808 до 9223372036854775807.

4. numeric/decimal:
4.1 Используется для значений c фиксированной точностью или масштабом.
4.2 Имеет переменный размер.
4.3 Имеет диапазон до 131072 цифр до точки и до 16383 после точки.

5. real (float4):
5.1 Используется для чисел с плавающей точкой.
5.2 Имеет размер 4 байта.
5.3 Имеет диапазон ~6–7 значимых цифр.

6. double precision (float8):
6.1 Используется для чисел с плавающей точкой.
6.2 Имеет размер 8 байт.
6.3 Имеет диапазон ~15–16 значимых цифр.

7. smallserial:
7.1 Используется для автоинкрементов (уступает IDENTITY).
7.2 Имеет размер 2 байта.
7.3 Имеет диапазон от 1 до 32767.

8. serial:
8.1 Используется для автоинкрементов (уступает IDENTITY).
8.2 Имеет размер 4 байта.
8.3 Имеет диапазон от 1 до 2147483647.

9. bigserial:
9.1 Используется для автоинкрементов (уступает IDENTITY).
9.2 Имеет размер 8 байт.
9.3 Имеет диапазон от 1 до 9223372036854775807.

Начиная с PG 10, вместо типа "serial" лучше использовать стандартизированные столбцы:
GENERATED { BY DEFAULT | ALWAYS } AS IDENTITY. Это чище с точки зрения схемы и прав.

/*--------------------------------------------------------------------------------------------------------------------*/

Символьные типы в PostgreSQL:

1. varchar(n) - используется для строк переменной длины, ограниченных n.
2. char(n) - используется для строк фиксированной длины n.
3. text - используется для строк произвольной длины.

/*--------------------------------------------------------------------------------------------------------------------*/

Логический тип в PostgreSQL представлен как "boolean (bool)".

Типы даты и времени в PostgreSQL:

1. timestamp[(p)] without time zone:
1.1 Используется для дат и времени без часового пояса.
1.2 Имеет размер 8 байт.
1.3 Имеет диапазон от 4713 до н.э. до 294276 н.э.
1.4 Имеет точность до 1 мкс.

2. timestamp[(p)] with time zone (timestamptz):
2.1 Используется для дат и времени с часовым поясом.
2.2 Имеет размер 8 байт.
2.3 Имеет диапазон от 4713 до н.э. до 294276 н.э.
2.4 Имеет точность до 1 мкс.

3. date:
3.1 Используется для дат.
3.2 Имеет размер 4 байта.
3.3 Имеет диапазон от 4713 до н.э. до 5874897 н.э.
3.4 Имеет точность 1 день.

4. time[(p)] without time zone:
4.1 Используется для времени без часового пояса.
4.2 Имеет размер 8 байт.
4.3 Имеет диапазон от 00:00:00 до 24:00:00.
4.4 Имеет точность до 1 мкс.

5. time[(p)] with time zone (timetz):
5.1 Используется для времени с часовым поясом.
5.2 Имеет размер 12 байт.
5.3 Диапазон зависит от пояса.
5.4 Имеет точность до 1 мкс.

6. interval:
6.1 Используется для промежутков времени.
6.2 Имеет размер 16 байт.
6.3 Имеет диапазон ~±178 млн лет.
6.4 Имеет точность до 1 мкс.

Лучше хранить "реальное время события" в типе "timestamptz". Тип "timestamptz не сохраняет часовой пояс внутри себя -
под капотом PostgreSQL переводит любое переданное время в UTC и сохраняет его как 8 байт, а при чтении БД смотрит на
часовой пояс клиента (сессии) и отдает время, смещенное относительно UTC под часовой пояс пользователя. Тип "timetz"
почти не нужен. Для длительностей лучше использовать тип "interval".

/*--------------------------------------------------------------------------------------------------------------------*/

Дополнительные часто используемые типы в PostgreSQL:

1. uuid - это 128‑битный идентификатор, который может использоваться для внешних ключей или ID без угадываемых
последовательностей.
2. bytea - это бинарные данные, которые могут использоваться для небольших бинарных блобов, так как большие блобы лучше
хранить в объектном хранилище.
3. json - это текст JSON, который может использоваться для хранения значение в пришедшем виде.
4. jsonb - это бинарный JSON, который может использоваться для поиска и индексации. Тип jsonb обычно предпочтительнее
типа json. Для поиска по JSON стоит использовать операторы "->", "->>" и "@>".
5. ARRAY - это массивы любых базовых типов, которые могут использоваться когда массив логичен и редко фильтруется по
элементам, иначе стоит делать нормализацию.
6. ENUM - это перечисление значений, которое может использоваться для небольших стабильных списков статусов.
7. NULL - это не тип, а неизвестное или отсутствующее значение. С ним особая логика: сравнения дают NULL, поэтому нужно
использовать операторы "IS NULL" и "IS NOT NULL", а не "=" и "<>".

В отличие от MongoDB, в PostgreSQL сначала нужно продумать и создать таблицы, а уже потом подключаться к серверу БД в
NestJS.

/*--------------------------------------------------------------------------------------------------------------------*/

В PostgreSQL есть индексы, как и в MongoDB.

/*--------------------------------------------------------------------------------------------------------------------*/

Primary key (PK) - это ограничение на поле, определяющее записи в таблице. В таблице может быть только один PK. PK
всегда уникальный.

PK может быть составным, то есть состоять из нескольких полей. При составном PK значения в полях, из которых он состоит,
могут повторяться, но не могут повторяться комбинации значений в этих полях.

PK автоматический создает индекс для поля.

Foreign key (FK) - это поле определяющее записи в текущей таблице в текущей таблице, которое ссылается на поле из
внешней таблицы. FK нужно создавать на те поля других таблиц, которые гарантированно уникальные. FK позволяет связывать
несколько таблиц, обеспечивая целостность данных гарантией, что связанные данные в разных таблицах согласованы. В
таблице может быть больше одного FK.

Если попытаться удалить запись из внешней таблицы, по FK которой есть запись в текущей таблице, то в зависимости от
настроек таблицы будет либо ошибка, либо каскадное удаление зависимых записей.

Отличия PK от поля с ограничением "UNIQUE":
1. PK может быть только один на таблицу, когда полей с ограничением "UNIQUE" может быть сколько угодно.
2. PK не может быть NULL.
3. Смысл PK идентифицировать запись, когда задача ограничения "UNIQUE" просто гарантировать уникальность значений в
поле.

Как на PK, так и просто на поле с ограничением "UNIQUE", можно создавать FK.

FK может быть составным:
1. Если ссылается на составной PK.
2. Если ссылается на несколько уникальных полей, комбинация которых помечена как уникальная: UNIQUE (field1, field2).

Одно и то же поле в таблице можно сделать одновременно и PK, и FK.

В PostgreSQL одинарные кавычки используются для указания строковых значений, когда двойные кавычки используются для
обращения к таблицам, полям и схемам, если их имена используют верхний регистр или специальные символы.

/*--------------------------------------------------------------------------------------------------------------------*/

В PostgreSQL при написании запросов ключевые слова не чувствительны к регистру, но принято писать их в верхнем регистре.

/*--------------------------------------------------------------------------------------------------------------------*/

Чтобы написать запрос в pgAdmin4 нужно в верхней левой части на панели значков выбрать "Query Tool".

/*--------------------------------------------------------------------------------------------------------------------*/

В запросах при указании имен таблиц, например, в "public.users" - "public" является именем схемы, и если запрос делается
в рамках этой схемы, то "public." можно не писать

/*--------------------------------------------------------------------------------------------------------------------*/

В PostgreSQL можно использовать:
1. Операторы сравнения:
1.1 Равенство: "=".
1.2 Неравенство: "<>" или "!=".
1.3 Меньше: "<".
1.4 Меньше или равно: "<=".
1.5 Больше: ">".
1.6 Больше или равно: ">=".
2. Арифметические операторы:
2.1 Сложение: "+".
2.2 Вычитание: "-".
2.3 Умножение: "*".
2.4 Деление: "/".
2.5 Деление по модулю: "%".

/*--------------------------------------------------------------------------------------------------------------------*/

Использование конкатенации в чистых запросах в приложении может быть опасно, так как при конкатенации пользовательский
ввод встраивается прямо в текст запроса, что открывает возможность для SQL-инъекций. Безопаснее использовать
параметризованные запросы, так как они передают ввод отдельно от кода, поэтому СУБД воспринимает его только как данные.
Использование конкатенация может быть допустимо только для неизменяемых технических элементов, например, при подстановке
проверенного имени колонки из разрешенного списка полей для сортировки, так как имена полей нельзя параметризовать.

/*--------------------------------------------------------------------------------------------------------------------*/

Операторы в PostgreSQL:

1. Оператор "CREATE" - это оператор, позволяющий создавать новые объекты в БД:
1.1 После оператора "CREATE" требуется указывать ключевые слова, поясняющие какой именно объект необходимо
создать:
- CREATE DATABASE - БД.
- CREATE TABLE - таблица.
- CREATE INDEX - индекс.
- CREATE SCHEMA - схема.
- CREATE VIEW - представление.
- CREATE MATERIALIZED VIEW - материализованное представление.
- CREATE SEQUENCE - последовательность.
- CREATE FUNCTION - функция.
- CREATE PROCEDURE - процедура.
- CREATE TRIGGER - триггер.
- CREATE TYPE - пользовательский тип данных.
- CREATE DOMAIN - домен (тип с ограничениями).
- CREATE ROLE - роль или пользователь.
- CREATE EXTENSION - расширение.
- CREATE TABLESPACE - табличное пространство.
- CREATE AGGREGATE - агрегатная функция.
- CREATE OPERATOR - оператор.
- CREATE RULE - правило.
- CREATE POLICY - политика безопасности.
- CREATE PUBLICATION - публикация (репликация).
- CREATE SUBSCRIPTION - подписка (репликация).
- CREATE COLLATION - правило сортировки.
- CREATE CONVERSION - преобразование кодировок.
- CREATE FOREIGN DATA WRAPPER - обертка внешних данных.
- CREATE SERVER - внешний сервер.
- CREATE FOREIGN TABLE - внешняя таблица.
- CREATE USER MAPPING - маппинг пользователя.
- CREATE STATISTICS - расширенная статистика.
- CREATE TRANSFORM - преобразование типа.
- CREATE LANGUAGE - процедурный язык.
- CREATE CAST - приведение типов.
- CREATE EVENT TRIGGER - событийный триггер.
- CREATE ACCESS METHOD - метод доступа.
- CREATE GROUP - группа (устаревший синоним CREATE ROLE).
- CREATE TEXT SEARCH CONFIGURATION - конфигурация полнотекстового поиска.
- CREATE TEXT SEARCH DICTIONARY - словарь полнотекстового поиска.
- CREATE TEXT SEARCH PARSER - парсер полнотекстового поиска.
- CREATE TEXT SEARCH TEMPLATE - шаблон полнотекстового поиска.
1.2 После ключевого слова, поясняющего какой именно объект необходимо создать, требуется указания имени для создаваемого
объекта.
1.3 Для указания дополнительных параметров требуется использования ключевого слова "WITH". Какие именно дополнительные
параметры можно указывать зависит от типа создаваемого объекта. Значение дополнительного параметра указывается при 
помощи знака "=". Например, дополнительные параметры при создании БД для "CREATE DATABASE":
- OWNER - имя пользователя, который будет владельцем БД.
- TEMPLATE - имя базы-шаблона, с которой скопируется структура, по умолчанию "template1".
- ENCODING - кодировка базы.
- LOCALE - общие региональные настройки.
- LC_COLLATE - правило сортировки строк.
- LC_CTYPE - классификация символов, например, что считается буквой, регистры.
- LOCALE_PROVIDER - поставщик локалей, например "libc" или "icu".
- ICU_LOCALE - локаль для провайдера ICU, например, "en-US".
- ICU_RULES - кастомные правила сортировки для ICU.
- COLLATION_VERSION - версия правил сортировки.
- TABLESPACE - имя табличного пространства, где необходимо хранить файлы БД, по умолчанию, "pg_default".
- CONNECTION LIMIT - максимальное количество одновременных подключений, если указано -1, то без ограничений.
- ALLOW_CONNECTIONS - разрешать ли подключаться к БД.
- IS_TEMPLATE - сделать ли эту БД шаблоном для создания других БД.
- STRATEGY - способ копирования шаблона, например, "WAL_LOG" или "FILE_COPY".
1.4 При создании таблицы для "CREATE TABLE" очень редко используется ключевое слово "WITH", но всегда указываются
настройки полей таблицы в круглых скобках. В этих настройках для того, чтобы пометить какое-то поле как PK, нужно
использовать ограничение "PRIMARY KEY" после указания типа поля или указать имя поля так: "PRIMARY KEY (field_name)".
При описании поля таблицы можно использовать ограничение "NOT NULL", чтобы указать, что это поле не может быть NULL.
Также при описании поля таблицы можно использовать свойство поля "DEFAULT" для задания значения по умолчанию. Если
нужно пометить какое-то поле как FK, то можно использовать ограничение "FOREIGN KEY (field_name)", при этом после
этого можно использовать:
- Ключевое слово "REFERENCES" для указания, на какую таблицу и поле ссылается этот FK.
- Ключевые слова "MATCH SIMPLE" для указания режима проверки составных FK, где ключевое слово "SIMPLE" допускает NULL в
части полей (указано по умолчанию).
- Опция ограничения "ON UPDATE NO ACTION" для указания запрещать изменять поле, на которое ссылается FK (указано по
умолчанию).
- Опция ограничения "ON DELETE NO ACTION" для указания запрещать удалять запись, на которую ссылается FK (указано по
умолчанию).
Также какое-то поле можно пометить как FK путем указания ключевого слова "REFERENCES" после типа поля.
1.5 Примеры:

1.5.1 Создание БД:

CREATE DATABASE "Examples_001"
	WITH
		OWNER = postgres
		ENCODING = 'UTF8'
		LOCALE_PROVIDER = 'libc'
		CONNECTION LIMIT = -1
		IS_TEMPLATE = false;

1.5.2 Создание таблицы c PK:

CREATE TABLE users (
	id SERIAL PRIMARY KEY,
	first_name VARCHAR,
	last_name VARCHAR,
	passport_number VARCHAR,
	is_married BOOLEAN
);

или

CREATE TABLE public.users (
	id serial,
	first_name character varying,
	last_name character varying,
	passport_number character varying,
	is_married boolean,
	PRIMARY KEY (id)
);

1.5.3 Создание таблицы с PK и FK:

CREATE TABLE public.wallets (
	id UUID NOT NULL DEFAULT gen_random_uuid() PRIMARY KEY,
	title VARCHAR,
	currency CHAR(3),
	owner_id INT,
	FOREIGN KEY (owner_id)
		REFERENCES public.users (id) MATCH SIMPLE
		ON UPDATE NO ACTION
		ON DELETE NO ACTION
);

1.5.4 Создание таблицы с PK и двумя FK:

CREATE TABLE public.wallets_sharing (
	id UUID DEFAULT gen_random_uuid() PRIMARY KEY,
	wallet_id UUID,
	user_id INT,
	added_date DATE DEFAULT CURRENT_DATE,
	status SMALLINT,
	FOREIGN KEY (wallet_id)
		REFERENCES public.wallets (id) MATCH SIMPLE
		ON UPDATE NO ACTION
		ON DELETE NO ACTION,
	FOREIGN KEY (user_id)
		REFERENCES public.users (id) MATCH SIMPLE
		ON UPDATE NO ACTION
		ON DELETE NO ACTION
);

1.5.5 Создание таблицы, где одно и то же поле является и PK, и FK:

CREATE TABLE public.profiles (
    hobby VARCHAR,
    education VARCHAR,
    user_id INT NOT NULL PRIMARY KEY,
    FOREIGN KEY (user_id)
        REFERENCES public.users (id)
		MATCH SIMPLE
        ON UPDATE NO ACTION
        ON DELETE NO ACTION
);

2. Оператор "INSERT" - это оператор, позволяющий добавлять новые записи в таблицу:
2.1 Может использоваться с необязательным ключевым словом "INTO".
2.2 После оператора "INSERT" или ключевого слова "INTO" требуется указание имени таблицы с перечислением в круглых
скобках имен полей этой таблицы.
2.3 После перечисления полей таблицы требуется использовать ключевое слово "VALUES" с перечислением в круглых скобках
значений полей в записи в том же порядке, в котором они были указаны после оператора "INSERT" или ключевого слова
"INTO".
2.4 Через запятую можно указывать круглые скобки несколько раз, если нужно добавить больше одной записи в таблицу.
2.5 В конце можно использовать ключевое слово "RETURNING *", чтобы получить все добавленные записи со значениями всех
полей, или же вместо "*" указать имена конкретных полей.
2.6 Примеры:

2.6.1 Добавление новой записи в таблицу:

INSERT INTO public.users (first_name, last_name, passport_number, is_married)
	VALUES ('John', 'Smith', '123456', false);

2.6.2 Добавление нескольких новых записей в таблицу и их получение:

INSERT INTO	public.users (first_name, last_name, passport_number, is_married)
	VALUES
		('John', 'Smith', '123456', false),
		('Adam', 'Kim', '345234', false),
		('Marie', 'Oak', '772141', true),
		('Susan', 'Sage', '910211', false),
		('Mag', 'Bullets', '119213', true),
		('Phill', 'Connor', '221590', true)
RETURNING *;

или

INSERT INTO	public.profiles (hobby, education, user_id)

3. Оператор "AS" - это оператор, позволяющий создавать псевдонимы для имен таблиц, полей и так далее:
3.1 Указывается сразу после первого использования через пробел.
3.2 Во всех случаях, кроме случая создания таблицы оператор "AS" может быть опущен для создания псевдонима.
3.3 Примеры:

3.3.1 Получение данных таблицы по определенным полями, используя псевдоним для таблицы:

SELECT id, u.first_name, u.last_name, u.passport_number, u.is_married
	FROM public.users u;

или

SELECT id, u.first_name, u.last_name, u.passport_number, u.is_married
	FROM public.users AS u;

или

SELECT id, u.first_name, u.last_name, u.passport_number, u.is_married
	FROM public.users AS "u";

4. Оператор "SELECT" - это оператор, позволяющий получать данные таблиц:
4.1 После оператора "SELECT" требуется через запятую перечислить имена полей, данные по которым нужно получить,
или указать "*", если нужно получить данные по всем полям.
4.2 После перечисления имен полей требуется использовать ключевое слово "FROM" для указания имени таблицы, данные из
которой нужно получить.
4.3 После ключевого слова "FROM" можно использовать оператор "WHERE" для указания условий поиска данных в таблице.
В работе оператора "WHERE" нельзя использовать агрегатные функции, например, такие, как "COUNT(*)", "SUM()" или "AVG()".
Оператор "WHERE" работает с каждой записью по отдельности до подсчетов и группировок. Оператор "WHERE" может работать со
следующими операциями:
- Сравнения: "=", "<>" или "!=", ">", "<", ">=", "<=".
- Проверка диапазона при помощи операторов "BETWEEN" и "AND": WHERE field_name BETWEEN num_01 AND num_02.
- Проверка по включению в список при помощи оператора "IN": WHERE field_name IN (num_01, num_02, num_03).
- Проверка по отсутствии в списке при помощи оператора "NOT IN":
WHERE field_name NOT IN (num_01, num_02, num_03).
- Поиск по шаблону при помощи операторов "LIKE" и "ILIKE". Могут использовать с ключевым словом "ESCAPE" для
экранирования: WHERE email '%y!_%' ESCAPE '!'. Без ключевого слова "ESCAPE" для экранирования нужно использовать символ
"\": WHERE email '%y\_%'. В операторах "LIKE" и "ILIKE" символ "%" обозначает любое количество любых символов, а символ
"_" - ровно один любой символ.
- Проверка на NULL при помощи операторов "IS NULL" и "IS NOT NULL".
- Логические связки при помощи операторов "AND", "OR" и "NOT".
4.4 В конце запроса можно использовать оператор "ORDER BY" для сортировки получаемых данных. Этот оператор можно
комбинировать с ключевыми словами "LIMIT" и "OFFSET" для имитации пагинации данных.

4.5 Примеры:

4.5.1 Получение данных таблицы по определенным полям:

SELECT id, first_name, last_name, passport_number, is_married
	FROM public.users;

4.5.2 Получение данных таблицы по всем полям:

SELECT *
	FROM public.users;

4.5.3 Получение данных таблицы по всем полям по условию:

SELECT *
	FROM public.users
	WHERE id = 3;

4.5.4 Получение данных таблицы по всем полям по составному условию ('123%' означает, что поле должно начинаться со
строки "123"):

SELECT *
	FROM public.users
	WHERE
		is_married = false
		AND passport_number LIKE '123%';

4.5.5 Получение данных таблицы по всем полям по составному условию ('%456' означает, что поле должно заканчиваться на
строку "456"):

SELECT *
	FROM public.users
	WHERE
		is_married = false
		AND passport_number LIKE '%456';

4.5.6 Получение данных таблицы по всем полям по составному условию ('%234%' означает, что поле должно содержать строку
"234"):

SELECT *
	FROM public.users
	WHERE
		is_married = false
		AND passport_number LIKE '%234%';

4.5.7 Получение данных таблицы по всем полям с сортировкой по убыванию по указанному полю:

SELECT *
	FROM public.users
	ORDER BY id DESC;

4.5.8 Получение данных таблицы по всем полям с сортировкой по возрастанию по указанному полю, получая только две записи
и пропуская первую:

SELECT *
	FROM public.users
	ORDER BY id ASC
	    LIMIT 2 OFFSET 1;

4.5.9 Получение данных таблицы по всем полям с установкой дополнительного поля для всех записей, используя подзапрос:

SELECT *, (
	SELECT first_name || ' ' || last_name AS boss_name
		FROM public.users
		WHERE id = 1
	)
	FROM public.users;

5. Оператор "ALTER" - это оператор, позволяющий изменять объекты в БД:
5.1 После оператора "ALTER" требуется указывать ключевые слова, поясняющие какой именно объект необходимо изменить:
- ALTER TABLE - таблица.
- ALTER DATABASE - БД.
- ALTER INDEX - индекс.
- ALTER SCHEMA - схема.
- ALTER VIEW - представление.
- ALTER MATERIALIZED VIEW - материализованное представление.
- ALTER SEQUENCE - последовательность.
- ALTER FUNCTION - функция.
- ALTER PROCEDURE - процедура.
- ALTER TRIGGER - триггер.
- ALTER TYPE - пользовательский тип.
- ALTER DOMAIN - домен.
- ALTER ROLE - роль или пользователь.
- ALTER EXTENSION - расширение.
- ALTER TABLESPACE - табличное пространство.
- ALTER AGGREGATE - агрегатная функция.
- ALTER OPERATOR - оператор.
- ALTER RULE - правило.
- ALTER POLICY - политика безопасности.
- ALTER PUBLICATION - публикация.
- ALTER SUBSCRIPTION - подписка.
- ALTER COLLATION - правило сортировки.
- ALTER CONVERSION - преобразование кодировок.
- ALTER FOREIGN DATA WRAPPER - обертка внешних данных.
- ALTER SERVER - внешний сервер.
- ALTER FOREIGN TABLE - внешняя таблица.
- ALTER USER MAPPING - маппинг пользователя.
- ALTER STATISTICS - расширенная статистика.
- ALTER LANGUAGE - процедурный язык.
- ALTER EVENT TRIGGER - событийный триггер.
- ALTER DEFAULT PRIVILEGES - права по умолчанию.
- ALTER SYSTEM - глобальные настройки сервера.
- ALTER LARGE OBJECT - большой объект.
5.2 После ключевых слов, поясняющих какой именно объект необходимо изменить, требуется указывать имя изменяемого
объекта.
5.3 Между ключевыми словами, поясняющими какой именно объект необходимо изменить, и именем изменяемого объекта можно
указывать ключевые слова "IF EXISTS", чтобы избежать ошибки, если изменяемый объект не существует.
5.4 После ключевого слова, поясняющего какой именно объект необходимо изменить, или ключевых слов "IF EXISTS" требуется
указывать ключевые слова, описывающие какую именно операцию изменения необходимо провести. Например, список операций при
изменении таблицы для "ALTER TABLE":
- ADD COLUMN field_name type_name - добавление поля.
- DROP COLUMN field_name - удаление поля.
- ALTER COLUMN field_name TYPE type_name - изменение типа поля.
- ALTER COLUMN field_name SET NOT NULL - запретить NULL в поле.
- ALTER COLUMN field_name DROP NOT NULL - разрешить NULL в поле.
- ALTER COLUMN field_name SET DEFAULT value - задать значение по умолчанию для поля.
- ALTER COLUMN field_name DROP DEFAULT - удалить значение по умолчанию для поля.
- RENAME COLUMN field_name TO new_name - переименовать поле.
- RENAME TO new_name - переименовать таблицу.
- ADD CONSTRAINT constraint_name constraint - добавить именованное ограничение для поля, например, PK или FK.
- DROP CONSTRAINT constraint_name - удалить именованное ограничение для поля, например, PK или FK.
- ADD PRIMARY KEY (field_name) - добавить PK.
- ADD FOREIGN KEY (field_name) REFERENCES table_name(field_name) - добавить FK.
- ADD UNIQUE (field_name) - добавить ограничение уникальности.
- ADD CHECK check_constraint - добавить проверочное ограничение.
- OWNER TO new_user - сменить владельца таблицы.
- SET SCHEMA schema_name - переместить таблицу в другую схему.
- SET TABLESPACE tablespace_name - переместить файлы таблицы в другое место.
- ENABLE TRIGGER trigger_name - включить триггер.
- DISABLE TRIGGER trigger_name - отключить триггер.
- DISABLE TRIGGER ALL - отключить все триггеры.
- ENABLE RULE rule_name - включить правило.
- DISABLE RULE rule_name - отключить правило.
- SET (parameter = value) - изменить параметры хранения.
- RESET (parameter) - сбросить параметры хранения.
- SET LOGGED - включить ведение журнала.
- SET UNLOGGED - отключить ведение журнала.
- CLUSTER ON index_name - задать индекс для физической сортировки данных на диске.
- REPLICA IDENTITY FULL - настроить репликацию.
- ATTACH PARTITION partition_name FOR VALUES FROM value_01 TO value_02 - подключить секцию для секционированных таблиц.
- DETACH PARTITION partition_name - отключить секцию для секционированных таблиц.
- FORCE ROW LEVEL SECURITY - включить принудительную политику безопасности строк.
- NO FORCE ROW LEVEL SECURITY - отключить принудительную политику безопасности строк.
5.5 После ключевых слов, описывающих какую именно операцию изменения необходимо провести, в некоторых случаях можно
указывать ключевые слова "IF EXISTS" или "IF NOT EXISTS", чтобы избежать ошибки, если изменяемый объект не существует
или существует соответственно.

5.6 Примеры:

5.6.1 Добавление поля в таблицу:

ALTER TABLE IF EXISTS public.users
	ADD COLUMN city VARCHAR;

5.6.2 Удаление поля из таблицы:

ALTER TABLE IF EXISTS public.users
	DROP COLUMN city;

5.6.3 Переименование таблицы:

ALTER TABLE IF EXISTS public.users
	RENAME TO people;

5.6.4 Переименование поля в таблице:

ALTER TABLE IF EXISTS public.users
	RENAME COLUMN passport_number TO passport;

5.6.5 Добавление уникального ограничения, чтобы нельзя было добавить больше одной записи по одним и тем же значениям
двух полей:

ALTER TABLE IF EXISTS public.wallets_sharing
	ADD UNIQUE (wallet_id, user_id);

6. Оператор "UPDATE" - это оператор, позволяющий изменять значения в записях:
6.1 После оператора "UPDATE" требуется указывать имя таблицы, в которой необходимо изменить значения в записях.
6.2 После имени таблицы, в которой необходимо изменить значения в записях, требуется указывать ключевое слово "SET" и
при помощи знака "=" указать имя поля и новое значение: "SET field_name = new_value". Если нужно поменять значения по
нескольким полям, то их можно перечислить через запятую.
6.3 Если нужно использовать данные из другой таблицы, то можно использовать ключевое слово "FROM" с указанием после него
имени таблицы.
6.4 Если нужно изменить значение только в определенных записях, а не во всех, то можно использовать оператор "WHERE" в
конце запроса с указанием после него условия поиска.
6.5 В конце можно использовать ключевое слово "RETURNING *", чтобы получить все измененные записи со значениями всех
полей, или же вместо "*" указать имена конкретных полей.
6.6 Примеры:

6.6.1 Изменение значения поля по условию:

UPDATE public.wallets
	SET title = 'Useless Money'
	WHERE owner_id = 4;

7. Оператор "DELETE" - это оператор, позволяющий удалять записи в таблице:
7.1 После оператора "DELETE" требуется указывать ключевое слово "FROM" и имя таблицы, в которой необходимо удалить
записи.
7.2 Если нужно использовать данные из другой таблицы, то можно использовать ключевое слово "USING" с указанием после
него имени таблицы.
7.3 Если нужно удалить только определенные записи, а не все, то можно использовать оператор "WHERE" в конце запроса с
указанием после него условия поиска.
7.4 В конце можно использовать ключевое слово "RETURNING *", чтобы получить все удаленные записи со значениями всех
полей, или же вместо "*" указать имена конкретных полей.
7.5 Примеры:

7.5.1 Удаление записей в таблице:

DELETE FROM public.wallets
	WHERE owner_id = 1;

8. Оператор "TRUNCATE" - это оператор, позволяющий удалять все записи в таблице, причем работая быстрее на больших
таблицах, чем оператор "DELETE", так как не удаляет записи по одной, а просто очищает файлы данных целиком:
8.1 Может использоваться с необязательным ключевым словом "TABLE".
8.2 После оператора "TRUNCATE" или ключевого слова "TABLE" требуется указывать имя таблицы, в которой нужно удалить все
записи.
8.3 После имени таблицы, в которой нужно удалить все записи, можно указывать опции "RESTART IDENTITY" или
"CONTINUE IDENTITY" для указания нужно ли сбрасывать счетчики или нет.
8.4 После опций "RESTART IDENTITY" или "CONTINUE IDENTITY" можно указывать опции "CASCADE" или "RESTRICT", если нужно
очистить также все таблицы, которые ссылаются на текущую таблицу через FK, или если нужно запретить очистку таблицы,
если есть ссылающиеся на нее таблицы, что является значением по умолчанию.
8.5 Примеры:

8.5.1 Удаление всех записей в таблице со сбросом счетчиков:

TRUNCATE TABLE public.users RESTART IDENTITY;

8.5.2 Удаление всех записей в таблице без сброса счетчиков:

TRUNCATE TABLE public.users CONTINUE IDENTITY;

10. Оператор "JOIN" - это оператор, используемый для объединения записей из двух и более таблиц на основе условия связи
между ними:
10.1 Виды оператора "JOIN":
- "INNER JOIN" / "JOIN" - это оператор, объединяющий данные из двух таблиц, когда в результат попадают только те записи,
для которых совпадение найдено в обеих таблицах.
- "LEFT JOIN" - это оператор, объединяющий данные из двух таблиц, когда в результат попадают все записи из левой таблицы
и только совпадающие записи из правой таблицы, причем для несовпадающих записей поля правой таблицы заполняются NULL.
- "RIGHT JOIN" - это оператор, объединяющий данные из двух таблиц, когда в результат попадают все записи из правой
таблицы и только совпадающие записи из левой таблицы, причем для несовпадающих записей поля левой таблицы заполняются
NULL.
- "FULL OUTER JOIN" - это оператор, объединяющий данные из двух таблиц, когда в результат попадают все записи из обеих
таблиц, причем для несовпадающих записей поля противоположной таблицы заполняются NULL.
- "CROSS JOIN" - это оператор, объединяющий данные из двух таблиц, когда в результат попадают все возможные комбинации
записей, то есть каждая запись из первой таблицы соединяется с каждой записью из второй таблицы. Условие при помощи
ключевого слова "ON" не используется.
- "NATURAL JOIN" - это оператор, объединяющий данные из двух таблиц, при котором PostgreSQL автоматически определяет
условие связи по полям с одинаковыми именами в обеих таблицах. Условие при помощи ключевого слова "ON" не указывается.
10.2 Операторы "JOIN" используются внутри оператора "SELECT" после ключевого слова "FROM" и первой таблицы, но перед
оператором "WHERE".
10.3 Операторы "JOIN" не используются напрямую в операторах "UPDATE" и "DELETE", но ключевые слова "FROM" и "USING" и
оператор "WHERE" по сути позволяют имитировать работу операторов "JOIN".
10.4 Операторы "INNER JOIN", "LEFT JOIN", "RIGHT JOIN" и "FULL OUTER JOIN" требуют использования ключевого слова "ON"
для указания условия объединения записей в таблицах.
10.5 Можно использовать несколько операторов "JOIN" подряд для объединения более двух таблиц.
10.6 Примеры:

10.6.1 Объединение записей из двух таблиц, используя оператор "LEFT JOIN":

SELECT w.id, w.title, w.currency, w.owner_id, u.first_name, u.last_name
	FROM public.wallets AS w
	LEFT JOIN public.users AS u
	ON w.owner_id = u.id;

10.6.2 Объединение записей из двух таблиц, используя оператор "LEFT JOIN" и конкатенацию полей:

SELECT w.id, w.title, w.currency, w.owner_id, u.first_name || ' ' || u.last_name AS owner_full_name
	FROM public.wallets AS w
	LEFT JOIN public.users AS u
	ON w.owner_id = u.id;

или

SELECT w.id, w.title, w.currency, w.owner_id, CONCAT(u.first_name, ' ', u.last_name) AS owner_full_name
	FROM public.wallets AS w
	LEFT JOIN public.users AS u
	ON w.owner_id = u.id;

10.6.3 Объединение записей из двух таблиц, используя оператор "LEFT JOIN" и проверку на null:

SELECT *
	FROM public.users
	LEFT JOIN public.profiles
	ON public.users.id = public.profiles.user_id
	WHERE public.profiles.user_id IS NULL;

или

SELECT *
	FROM public.users
	LEFT JOIN public.profiles
	ON public.users.id = public.profiles.user_id
	WHERE public.profiles.user_id IS NOT NULL;

11. Агрегатная функция "COUNT" - это встроенная агрегатная функция, вычисляющая количество записей или значений и
возвращающая одно целое число типа "BIGINT":
11.1 Может принимать в круглых скобках символ "*", чтобы подсчитать все записи, попавшие в выборку, включая записи со
значениями NULL и дубликаты.
11.2 Может принимать в круглых скобках имя поля, чтобы подсчитать количество записей, где указанное поле не является
NULL.
11.3 Может принимать в круглых скобках ключевое слово "DISTINCT" и имя поля, чтобы подсчитать количество уникальных
значений, игнорируя дубликаты и NULL.
11.4 Используется внутри оператора "SELECT":
- Как с условием при помощи оператора "WHERE", так и без него.
- Вместе с оператором "GROUP BY" для подсчета количества в каждой группе.
- В операторе "HAVING" для фильтрации групп по количеству.
- В подзапросах.
11.5 Примеры:

11.5.1 Подсчет всех записей в таблице:

SELECT COUNT(*)
	FROM public.users;

11.5.2 Подсчет всех записей в таблице по условию:

SELECT COUNT(*) AS wallet_count
	FROM public.wallets
	WHERE owner_id = 1;

11.5.3 Подсчет всех записей в таблице по условию, используя подзапрос:

SELECT *, (
	SELECT COUNT(*)
		FROM public.wallets
		WHERE public.wallets.owner_id = public.users.id
	) AS wallet_count
	FROM public.users;

или

SELECT *, (
	SELECT COUNT(*) > 0
		FROM public.wallets
		WHERE public.wallets.owner_id = public.users.id
	) AS has_wallets
	FROM public.users;

или

SELECT *, (
	SELECT
		CASE WHEN COUNT(*) > 0
			THEN 'Yes'
			ELSE 'No'
		END
	FROM public.wallets
	WHERE public.wallets.owner_id = public.users.id
	) AS has_wallets
	FROM public.users;

12. Условная конструкция "CASE" - это условная конструкция, проверяющая условия по порядку и возвращающая значение
первого условия, которое оказалось true:
12.1 Возвращает значение, поэтому может использоваться везде, где можно написать имя поля или значение:
- В операторе "SELECT".
- Внутри агрегатных функций.
- В операторе "ORDER BY".
- В операторе "UPDATE".
- В операторе "WHERE".
12.2 Используется ключевое слово "WHEN" для описания условия.
12.3 Используется ключевое слово "THEN" для указания возвращаемых значений.
12.4 Может использоваться ключевое слово "ELSE" для указания результата, если ни одно условие не сработало.
12.5 Если ключевое слово "ELSE" не указано и ни одно условие не подошло, то вернется NULL.
12.6 Требуется использование ключевого слова "END" в конце конструкции.
12.7 Все ветки ключевых слов "THEN" и "ELSE" должны возвращать значения одного типа или совместимых типов.
12.8 Примеры:

12.8.1 Использование условной конструкции "CASE" для проверки произвольных логических условий:

SELECT title, balance,
	CASE
		WHEN balance > 1000
			THEN 'Rich'
		WHEN balance > 0
			THEN 'Normal'
		ELSE 'Empty'
	END AS status
FROM public.wallets;

12.8.2 Использование условной конструкции "CASE" для сравнения одного выражения со списком конкретных значений:

SELECT id, title,
	CASE status
		WHEN 1
			THEN 'Active'
		WHEN 2
			THEN 'Pending'
		WHEN 3
			THEN 'Blocked'
		ELSE 'Unknown'
	END AS status_name
FROM public.wallets_sharing
WHERE user_id = 4;

12.8.3 Использование условной конструкции "CASE" в агрегатной функции "COUNT":

SELECT
	COUNT(
		CASE
			WHEN is_married = true
				THEN 1
			END
	) AS married_count,
	COUNT(
		CASE
			WHEN is_married = false
				THEN 1
			END
	) AS single_count
FROM public.users;

12.8.4 Использование условной конструкции "CASE" в операторе "ORDER BY":

SELECT *
	FROM public.wallets
	ORDER BY
		CASE currency
			WHEN 'USD'
				THEN 1
			WHEN 'EUR'
				THEN 2
			ELSE 3
		END;

12.8.5 Использование условной конструкции "CASE" в операторе "UPDATE":

UPDATE public.wallets
	SET balance = CASE
		WHEN currency = 'USD'
			THEN balance * 1.1
		ELSE balance
	END;


13. Агрегатная функция "SUM" - это встроенная агрегатная функция, суммирующая числовые значения в указанном поле:
13.1 Может принимать в круглых скобках имя поля, чтобы суммировать все значения в поле, игнорируя NULL.
13.2 Может принимать в круглых скобках ключевое слово "DISTINCT" и имя поля, чтобы суммировать только уникальные
значения поля, игнорируя NULL.
13.3 Поле для суммирования значений обязано иметь числовой тип.
13.4 Если таблица пустая или в поле только NULL, то агрегатная функция "SUM" вернет NULL. Чтобы в таком случае
гарантированно получить 0 вместо NULL, нужно использовать агрегатную функцию "SUM" внутри функции "COALESCE".
13.5 Может использоваться:
- В операторе "SELECT".
- Вместе с оператором "GROUP BY".
- В операторе "HAVING".
- Внутри условной конструкции "CASE".
13.6 Примеры:

13.6.1 Подсчет суммы значений в поле по условию, используя оператор "WHERE":

SELECT SUM(balance)
	FROM public.wallets
	WHERE currency = 'USD';

13.6.2 Подсчет суммы значений в поле и их группировка:

SELECT currency, SUM(balance)
	FROM public.wallets
	GROUP BY currency;

13.6.3 Подсчет суммы значений в поле по условию и их группировка, используя оператор "HAVING":

SELECT currency, SUM(balance)
	FROM public.wallets
	GROUP BY currency
	    HAVING SUM(balance) > 10000;

13.6.4 Подсчет суммы значений в поле по условиям, используя условную конструкцию "CASE":

SELECT
	SUM(CASE
		WHEN currency = 'USD'
			THEN balance
			ELSE 0
		END) AS usd_total,
    SUM(CASE
		WHEN currency = 'EUR'
			THEN balance
			ELSE 0
		END) AS eur_total
FROM public.wallets;

14. Оператор "GROUP BY" - это оператор, группирующий строки по указанному полю или полям, "схлопывая" записи с
одинаковыми значениями в одну:
14.1 Используется в операторе "SELECT" вместе с агрегатными функциями после оператора "WHERE" и перед операторами
"HAVING" и "ORDER BY".
14.2 Если используется оператор "GROUP BY", то в операторе "SELECT" могут быть только поля, указанные в операторе
"GROUP BY", и агрегатные функции, например, "COUNT", "SUM", "AVG", "MIN" или "MAX".
14.3 Может группировать по нескольким полям, перечисленным через запятую.
14.4 Примеры:

14.4.1 Подсчет записей и их группировка по нескольким полям:

SELECT currency, owner_id, SUM(balance)
	FROM public.wallets
	GROUP BY currency, owner_id;

15. Оператор "HAVING" - это оператор, фильтрующий группы записей, полученные после работы оператора "GROUP BY":
15.1 Используется только в операторе "SELECT".
15.2 Может использоваться после оператора "GROUP BY", чтобы фильтровать полученные от него группы записей.
15.3 Может использоваться без оператора "GROUP BY", но в таком случае PostgreSQL будет воспринимать всю таблицу как одну
большую группу.
15.4 Требует указания после себя условия для фильтрации записей. Условия могут содержать агрегатные функции или поля,
которые явно перечислены в операторе "GROUP BY".
15.5 Примеры:

15.5.1 Подсчет записей по условию c отфильтрованной группировкой:

SELECT currency, COUNT(*)
	FROM public.wallets
	WHERE balance > 0
	GROUP BY currency
	    HAVING COUNT(*) > 1;

15.5.2 Подсчет суммы значений в поле с их фильтрацией:

SELECT SUM(balance)
	FROM public.wallets
	    HAVING SUM(balance) > 10000;


16. Оператор "ORDER BY" - это оператор, сортирующий записи в результирующем наборе данных по одному или нескольким
полям, или выражениям:
16.1 Используется только в операторе "SELECT" в самом конце запроса после операторов "WHERE", "GROUP BY" и "HAVING", но
перед ключевыми словами "LIMIT" и "OFFSET".
16.2 После него может указываться:
- Одно или несколько имен полей через запятую.
- Порядковые номера полей.
- Выражения и условная конструкция "CASE".
16.3 В конце оператора "ORDER BY" может указываться тип сортировки:
- "ASC" - сортировка по возрастанию, опция по умолчанию.
- "DESC" - сортировка по убыванию.
16.4 В PostgreSQL при сортировке NULL по умолчанию считаются самыми большими значениями, но это поведение можно явно
переопределить:
- ORDER BY balance ASC NULLS FIRST - NULL будут первыми при сортировке по возрастанию.
- ORDER BY balance DESC NULLS LAST - NULL будут последними при сортировке по убыванию.
16.5 После имени поля можно указать ключевое слово "COLLATE", чтобы задать правило сравнения строк. Например, следующий
вариант будет использовать сортировку строго по кодам символов ASCII, как это делает MongoDB:
ORDER BY login COLLATE "C" ASC.
16.6 Примеры:

16.6.1 Получение данных таблицы по всем полям с сортировкой по убыванию по указанному полю:

SELECT *
	FROM public.wallets
	ORDER BY balance DESC;

16.6.2 Получение данных таблицы по всем полям с сортировкой по убыванию по одному полю и с сортировкой по возрастанию по
другому полю:

SELECT *
	FROM public.users
	ORDER BY is_married DESC, last_name ASC;

16.6.3 Получение данных таблицы по всем полям с сортировкой по убыванию по указанному полю с ограничением количества
записей на вывод:

SELECT *
	FROM public.wallets
	ORDER BY balance DESC
		LIMIT 3;

16.6.4 Подсчет записей по условию c отфильтрованной группировкой и сортировкой с пагинацией:

SELECT currency, COUNT(*)
	FROM public.wallets
	WHERE balance > 0
	GROUP BY currency
		HAVING COUNT(*) > 1
	ORDER BY currency DESC
		LIMIT 5 OFFSET 0;

17. Агрегатная функция "AVG" - это встроенная агрегатная функция, вычисляющая среднее числовое значение в указанном
поле:
17.1 Имеет те же особенности, что и агрегатная функция "SUM".
17.2 Всегда возвращает дробное число, даже если поле целочисленное.

18. Агрегатные функции "MIN" и "MAX" - это встроенные агрегатные функции, находящие минимальное или максимальное
значение соответственно в указанном поле:
18.1 Имеют те же особенности, что и агрегатная функция "SUM".
18.2 Работают не только с числами, но и со строками и датами.

19. Оконная функция "ROW_NUMBER()" - это встроенная оконная функция, присваивающая каждой записи порядковый номер в
результирующем наборе:
19.1 Требует указания круглых скобок, хотя ничего и не принимает.
19.2 Требует использования ключевого слова "OVER", внутри которого в круглых скобках должно указываться правило
для нумерации, используя ключевые слова "ORDER BY" и "PARTITION BY". Ключевые слова "PARTITION BY" всегда должны идти до
ключевых слов "ORDER BY". Ключевое слово "OVER" может использовать не только в оконной функции "ROW_NUMBER()", но,
например, и в агрегатной функции "SUM".
19.3 Ключевые слова "ORDER BY" указывают в каком порядке нумеровать записи.
19.4 Ключевые слова "PARTITION BY" указывают когда сбрасывать счетчик на 1, то есть как будто разбивать на группы.
19.5 Примеры:

19.5.1 Получение данных таблицы по всем полям и нумерация записей:

SELECT *,
    ROW_NUMBER() OVER () AS row_number
	FROM public.wallets;

19.5.2 Получение данных таблицы по всем полям и их нумерация по полю:

SELECT *,
    ROW_NUMBER() OVER (ORDER BY owner_id) AS row_number
	FROM public.wallets;

19.5.3 Получение данных таблицы по всем полям, их нумерация по полю и фильтрация:

SELECT *
	FROM (
		SELECT *,
			ROW_NUMBER() OVER (ORDER BY owner_id) AS row_number
			FROM public.wallets
	)
	WHERE row_number > 0 AND row_number < 10;

19.5.4 Получение данных таблицы по всем полям, их нумерация по полю и фильтрация, используя оператор "WITH" (Common
Table Expression) для создания временного именованного набора данных:

WITH wallets_with_row_number AS (
	SELECT *,
		ROW_NUMBER() OVER (ORDER BY owner_id) AS row_number
		FROM public.wallets
)

SELECT *
	FROM wallets_with_row_number
	WHERE row_number > 0 AND row_number < 10;

19.5.5 Получение данных таблицы по всем полям, их нумерация по полю, сброс счетчика для каждого нового значения поля и
фильтрация:

SELECT *
	FROM (
		SELECT *,
			ROW_NUMBER() OVER (PARTITION BY owner_id ORDER BY owner_id) AS row_number
			FROM public.wallets
	)
	WHERE row_number > 0 AND row_number < 10;


19.5.6 Получение данных таблицы по всем полям и их нумерация по условию, используя условную конструкцию "CASE":

SELECT *,
	ROW_NUMBER() OVER (
		ORDER BY CASE
			WHEN currency = 'USD' THEN 1
			WHEN currency = 'RUB' THEN 2
			ELSE 3
		END
	) AS row_number
	FROM public.wallets;

19.5.7 Получение данных таблицы по всем полям, их нумерация по полю и сброс счетчика по условию, используя условную
конструкцию "CASE":

SELECT *,
	ROW_NUMBER() OVER (
		PARTITION BY CASE
			WHEN balance > 1000
				THEN 'rich'
				ELSE 'poor'
			END
		ORDER BY balance DESC
	) AS row_number
FROM public.wallets;

19.5.8 Получение данных таблицы по указанным полям с суммированием значений поля по группам, без использования оконной
функции "ROW_NUMBER()":

SELECT user_id, pay_sum, SUM (pay_sum) OVER (PARTITION BY user_id)
	FROM public.user_payments
	ORDER BY user_id;

20. Оператор "WHERE" - это оператор, фильтрующий строки по указанному условию:
20.1 Используется в операторах "SELECT", "UPDATE" и "DELETE".
20.2 В условиях может использовать операции сравнения и операторы "BETWEEN", "LIKE", "ILIKE", "IS NULL", "IS NOT NULL",
"AND", "OR" и "NOT".
20.3 Могут использоваться операторы "IN" и "NOT IN", для проверки входит ли значение в список или нет
соответственно. Если в списке есть хотя бы одно значение NULL, то оператор "NOT IN" вернет пустой результат, поэтому в
такой ситуации лучше использовать ключевые слова "NOT EXISTS" или оператор "NOT IN" с оператором "IS NOT NULL" в
подзапросе.

21. Оператор "::" - это оператор, приводящий тип.
21.1 Слева от оператора указывается значение, а справа от него - тип, к которому надо привести значение, например:
'123'::integer.
21.2 Аналогично оператору "::" можно использовать оператор "CAST": CAST (field_name AS TEXT).
21.3 Для не явного приведения типов можно использовать оператор конкатенации "||": '' || field_name.
21.4 Существует ряд встроенных функций для явного приведения типа: text(field_name).

21.5 Примеры:

21.5.1 Объединение двух таблиц с сортировкой по двум полям и приведением поля к строковому типу, используя оператор
"::":

SELECT id, username, email
	FROM public.users
UNION
SELECT id, number_login::TEXT, email
	FROM public.admins
ORDER BY id ASC, username ASC;

21.5.2 Объединение двух таблиц с сортировкой по двум полям и приведением поля к строковому типу, используя оператор
"CAST":
SELECT id,
username, email
	FROM public.users
UNION
SELECT id, CAST (number_login AS TEXT), email
	FROM public.admins
ORDER BY id ASC, username ASC;

21.5.3 Объединение двух таблиц с сортировкой по двум полям и приведением поля к строковому типу, используя оператор
конкатенации "||" для неявного приведения:

SELECT id, username, email
	FROM public.users
UNION
SELECT id, '' || number_login, email
	FROM public.admins
ORDER BY id ASC, username ASC;

21.5.4 Объединение двух таблиц с сортировкой по двум полям и приведением поля к строковому типу, используя функцию
"text":

SELECT id, username, email
	FROM public.users
UNION
SELECT id, text(number_login), email
	FROM public.admins
ORDER BY id ASC, username ASC;

22. Ограничение "CHECK" - это ограничение, проверяющее, что значение в поле соответствует заданному условию:
22.1 Применяется в операторах "CREATE TABLE", "ALTER TABLE" и "CREATE DOMAIN"
22.2 После ограничения "CHECK" должно указываться условие в круглых скобках.

23. Оператор "UNION" - это оператор, объединяющий результаты работы двух и более операторов "SELECT" в один вертикальный
список, где записи из второго запроса добавляются под записями из первого, причем имена колонок берутся из первого
запроса:
23.1 Требуется, чтобы оба оператора "SELECT" возвращали одинаковое количество полей, причем типы полей должны совпадать
или быть совместимыми.
23.2 Удаляет дубликаты, но можно использовать ключевое слово "ALL" после оператора "UNION", чтобы дубликаты не
удалялись, при этом вариант с ключевым словом "ALL" будет работать быстрее, так как не будет сортировки.
23.3 Примеры:

23.3.1 Объединение двух таблиц с сортировкой по двум полям:

SELECT id, username, email
	FROM public.users
UNION
SELECT id, login, email
	FROM public.admins

26. Представление "VIEW" - это сохраненный SQL-запрос, к которому можно обращаться как к обычной таблице:
26.1 Данные в представлении не хранятся.
26.2 Запрос "CREATE VIEW" создает представление, но выдаст ошибку, если представление с указанным именем уже существует.
26.3 Запрос "CREATE OR REPLACE VIEW" создает представление или заменяет уже существующее представление с указанным
именем, но не позволяет менять количество и типы полей.
26.4 Если использовать ключевое слово "MATERIALIZED" перед ключевым словом "VIEW", то это позволит кэшировать данные.
26.5 Запрос "ALTER VIEW" меняет метаданные представления, не трогая сам SQL-запрос.
26.6 Представления могут быть полезны для обеспечения безопасности данных, так как могут использоваться для создания
запросов, которые предоставляют только необходимые данные, избегая чувствительных.

	deleted_at TIMESTAMP DEFAULT NULL

	confirmation_code VARCHAR NOT NULL,
